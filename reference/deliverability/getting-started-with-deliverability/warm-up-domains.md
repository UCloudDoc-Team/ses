# 域名预热指南

域名预热是指在高并发发信前，通过可控、渐进的发送节奏建立发件信誉。  
其目标是让邮箱服务商逐步形成稳定信任，而不是在短时间内快速放量。

---

## 为什么预热是必需步骤

邮箱服务商会持续对域名和 IP 建模评分。  
对于缺少历史信誉或行为不连续的发件方，直接大规模发送通常会触发风控。

常见后果：
- 垃圾箱率上升
- 限流、延迟或拒收
- 域名/IP 信誉快速下滑
- 后续修复周期长、成本高

---

## 需要预热的典型场景

以下场景建议执行预热：
- 新域名或首次用于发信的子域名
- 停发一段时间后重新启用
- 更换 ESP、路由或发信 IP 池
- 计划显著提升发送规模
- 新增营销子域名（如 `marketing.example.com`）

这些场景的共性是：发信信誉尚未建立，或历史信誉已中断。

---

## 预热核心原则

### 1）低起点启动

初始发送量建议保持保守，例如：

```
Day 1: 50–200 封
```

起点过高通常会被识别为异常流量。

### 2）稳定递增

发送量按固定比例逐步增长，例如：

```
每日增长 20%–50%
```

需要避免突然翻倍或大幅波动，稳定性优先于增长速度。

### 3）优先高质量收件人

优先选择：
- 近期有打开/点击的用户
- 明确订阅用户
- 历史互动稳定的用户

避免使用冷名单、长期不活跃名单和来源不明名单。

### 4）合理分配服务商流量

尽量在主流服务商之间均衡分布，避免集中打到单一 ISP。

### 5）保持发送连续性

预热期应保持日级连续发送，避免中断和忽高忽低。

## 参考预热节奏（14 天示例）

以下计划可作为基线，实际应按指标动态调整：

| 天数     | 每日发送量 |
| ------ | ----- |
| 第 1 天  | 100   |
| 第 2 天  | 150   |
| 第 3 天  | 220   |
| 第 4 天  | 300   |
| 第 5 天  | 450   |
| 第 6 天  | 650   |
| 第 7 天  | 900   |
| 第 8 天  | 1200  |
| 第 9 天  | 1600  |

| 第 11 天 | 3000  |

| 第 14 天 | 7000+ |

如核心指标恶化，应暂停扩量并优先排查。

---

## 预热期间关键监控指标

建议按天监控以下指标：
- **投递成功率（Delivery Rate）**：建议 >= 95%
- **打开率（Open Rate）**：应保持在健康区间
- **投诉率（Complaint Rate）**：建议 < 0.1%
- **退信率（Bounce Rate）**：建议 < 2%

任何核心指标异常时，先稳住发送量，再定位原因。

---

## 不同邮件类型的预热差异

### 事务邮件

特点：
- 用户行为触发
- 互动率通常较高

建议：
- 可适度加快节奏
- 强调一致性和稳定性

### 营销邮件

特点：
- 活动驱动、批量发送
- 投诉敏感度更高

建议：
- 严格控制扩量速度
- 更依赖名单质量和分群策略

---

## 常见预热误区

1. Day 1 发送量过高  
2. 使用低质量或非订阅名单  
3. 发送节奏波动过大  
4. 多域名并行预热

建议：

> 按域名逐个完成预热，避免并行分散信誉积累。

---

## 如何判断预热完成

通常可参考以下条件：
- 收件箱到达率稳定（如 >= 85%）
- 打开率维持在健康水平
- 投诉率和退信率持续受控
- 扩量过程中未出现明显异常波动

预热完成后，应进入常态化信誉治理。

---

## 预热后的运营建议

- 保持可预测的发送节奏
- 避免突发式放量
- 持续进行名单清洗与抑制
- 基于互动数据优化内容和体验
- 定期复盘各邮箱服务商的投递表现
