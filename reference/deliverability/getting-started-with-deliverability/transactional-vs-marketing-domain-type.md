# 事务邮件与营销邮件：如何定义域名类型？

域名类型应在规模化发信前完成规划。  
在投递体系中，域名是长期信誉资产。若事务流量与营销流量混用同一域名，信誉信号会被混杂，关键通知邮件难以稳定保障。

---

## 定义与区别

### 事务邮件（Transactional）

事务邮件由用户行为触发，且用户通常预期会收到。  
常见场景包括注册验证、密码重置、订单确认、支付通知和系统告警。

### 营销邮件（Marketing）

营销邮件由企业主动发送，目标是推广、激活或转化。  
常见场景包括订阅通讯、活动推广、优惠信息和产品推荐。

### 运营特征差异

| 类型 | 用户预期 | 流量形态 | 投诉风险 |
| :--- | :--- | :--- | :--- |
| 事务邮件 | 高 | 事件触发、相对稳定 | 低 |
| 营销邮件 | 中/低 | 活动驱动、波动较大 | 较高 |

---

## 系统中的域名类型定义

### 事务型域名

满足以下任一条件即可归为事务型：
- 由明确用户行为触发
- 用户预期即时收到
- 属于关键服务流程环节

推荐命名示例：

```
notifications.yourdomain.com
system.yourdomain.com
mail.yourdomain.com
```

策略基线：
- 优先保障收件箱到达
- 严格内容与模板治理
- 不承载营销类流量

### 营销型域名

满足以下任一条件即可归为营销型：
- 批量或活动发送
- 目标为推广或转化
- 非即时用户行为触发

推荐命名示例：

```
marketing.yourdomain.com
news.yourdomain.com
promo.yourdomain.com
```

策略基线：
- 独立预热与信誉维护
- 持续名单清洗与抑制
- 控制投诉率在目标阈值内

---

## 为什么需要域名拆分

### 1）信誉隔离

邮箱服务商按域名评估信誉。域名拆分可以避免营销投诉直接影响事务邮件。

### 2）保障关键业务触达

验证码、支付通知等事务邮件对稳定性要求更高，拆分后能降低跨流量干扰。

### 3）策略隔离

| 类型 | 发送策略 |
| :--- | :--- |
| 事务邮件 | 实时触发、低波动 |
| 营销邮件 | 批量发送、分批节流 |

### 4）独立优化

可按流量类型和服务商维度分别优化打开率、点击率、投诉率与退信率。

---

## 按域名类型的推荐策略

### 事务型域名

- 保持稳定发信节奏
- 强制 SPF、DKIM、DMARC 对齐
- 严格管理发件人和模板
- 优先保障关键消息通道

### 营销型域名

- 活动流量分批发送
- 按服务商节奏控制
- 持续名单清洗和抑制
- 基于互动数据迭代内容

---

## 需要避免的做法

### 1）同一域名混发事务与营销

会显著提升关键通知被垃圾箱过滤的概率。

### 2）直接使用根域名发信

`yourdomain.com` 直接发信会放大品牌主域信誉风险。

### 3）频繁更换发信域名

会阻断信誉积累，导致送达表现长期不稳定。

---

## 推荐域名架构示例

```
根域名：
yourdomain.com

事务邮件：
- mail.yourdomain.com
- notify.yourdomain.com

营销邮件：
- marketing.yourdomain.com
- promo.yourdomain.com

追踪域名：
- track.xxx.yourdomain.com
```

---

## 在系统中如何选择域名类型

创建发信域名时：
- 系统通知、用户触发消息：选择**事务型**
- 活动推广、批量触达消息：选择**营销型**

选择后，平台会按域名类型应用对应的投递策略、速率控制和风险阈值。
