# 遵守 Gmail、Yahoo、Microsoft 对邮件发件人的要求

## 一、背景与目标

随着主流邮箱服务商持续收紧反垃圾邮件策略，发件人必须满足更严格的合规要求，才能保证邮件正常投递至收件箱。

若不符合规范，可能带来的影响包括：

* 邮件进入垃圾箱或被拦截
* 投递失败（拒收或限流）
* 发信域名或 IP 信誉下降
* 严重情况下被永久限制发送

本指南旨在明确关键合规要求，帮助发件人建立稳定、可持续的发送能力。

---

## 二、适用范围

本规范适用于通过平台发送的所有邮件类型，包括但不限于：

* 营销邮件
* 事务邮件（如验证码、订单通知）
* 系统通知邮件

---

## 三、核心合规要求概览

| 分类    | 要求                 | 是否强制    | 适用服务商                     |
| ----- | ------------------ | ------- | ------------------------- |
| 邮件认证  | SPF / DKIM / DMARC | 是       | Gmail / Yahoo / Microsoft |
| 用户授权  | 明确订阅               | 是       | 全部                        |
| 退订机制  | 一键退订               | 是（营销邮件） | Gmail / Yahoo             |
| 投诉率控制 | < 0.3%             | 是       | Gmail / Yahoo             |
| 内容规范  | 无欺诈、无误导            | 是       | 全部                        |
| 域名对齐  | 发件域一致              | 是       | Gmail / Yahoo             |
| 列表质量  | 禁止购买或抓取邮箱          | 是       | 全部                        |

---

## 四、详细合规要求

### 4.1 邮件认证

#### 基础要求

必须完整配置以下 DNS 认证记录：

* SPF（Sender Policy Framework）
* DKIM（DomainKeys Identified Mail）
* DMARC（Domain-based Message Authentication, Reporting, and Conformance）

#### 配置要点

* **SPF**：覆盖所有合法发信来源（IP 或服务商）
* **DKIM**：启用签名，并确保签名域名与发件域一致
* **DMARC**：

  * 最低要求：`p=none`
  * 推荐策略：`p=quarantine` 或 `p=reject`

#### 对齐要求（Alignment）

需满足以下对齐关系：

* 发件头域名 ≈ DKIM 签名域名
* 发件头域名 ≈ SPF 域名

未对齐通常会被判定为高风险行为。

---

### 4.2 用户授权（订阅机制）

#### 强制要求

* 必须获得用户明确授权后方可发送邮件
* 禁止以下行为：

  * 使用购买的邮箱列表
  * 抓取或导入未经授权的数据
  * 向未订阅用户发送营销邮件

#### 推荐实践

* 使用双重订阅确认（Double Opt-in）
* 在注册或收集邮箱时明确说明邮件用途

---

### 4.3 退订机制

#### 强制要求（营销邮件）

* 必须提供一键退订能力
* 必须支持标准退订头（List-Unsubscribe）

#### 技术示例

```
List-Unsubscribe: <mailto:unsubscribe@domain.com>, <https://domain.com/unsubscribe>
List-Unsubscribe-Post: List-Unsubscribe=One-Click
```

#### 体验要求

* 邮件正文中需提供清晰可见的退订入口
* 不得隐藏、弱化或增加不必要的退订步骤

---

### 4.4 投诉率控制

#### 标准要求

* Gmail / Yahoo：投诉率需低于 0.3%
* 建议目标：控制在 0.1% 以下

#### 计算方式

```
投诉率 = 投诉次数 / 成功投递量
```

#### 风险说明

* 投诉率过高将直接影响收件箱投递
* 持续超标可能导致域名或 IP 被限制使用

---

### 4.5 内容规范

#### 禁止行为

* 使用误导性或夸张标题
* 冒充他人或品牌身份
* 诱导点击或隐藏真实意图

#### 推荐做法

* 保持主题与内容一致
* 明确标识发件人身份
* 提供真实可验证的企业信息

---

### 4.6 发送行为规范

#### 发送策略

* 避免短时间内发送量激增
* 新域名必须进行预热
* 保持发送节奏稳定

#### 用户分层

* 优先发送给高活跃用户
* 降低或停止向长期无互动用户发送

---

### 4.7 列表健康管理

#### 强制要求

需定期清理以下用户：

* 硬退信地址（永久不可达）
* 多次软退信地址
* 长期无互动用户

#### 推荐策略

| 用户状态     | 处理方式    |
| -------- | ------- |
| 30 天未打开  | 降低发送频率  |
| 90 天未打开  | 发起再激活活动 |
| 180 天未打开 | 移出发送列表  |

---

## 五、平台能力支持

为帮助用户满足上述要求，平台提供以下能力支持：

### 5.1 合规检测与评分

提供自动化检测能力，包括：

* SPF / DKIM / DMARC 配置校验
* 投诉率与退信率监控
* 发信行为分析

输出结果：

* 合规评分（0–100）
* 风险等级（低 / 中 / 高）

---

### 5.2 接入与配置引导

降低技术门槛，支持：

* 自动生成 DNS 配置记录
* 一键复制与接入指引
* 实时校验配置状态

---

### 5.3 风控策略引擎

在检测到风险行为时，系统将自动执行控制策略：

| 风险类型   | 处理策略   |
| ------ | ------ |
| 投诉率异常  | 限制发送速率 |
| 未完成认证  | 拦截发送   |
| 命中垃圾陷阱 | 暂停账号   |

---

### 5.4 投递与表现分析

提供多维度数据支持，包括：

* 收件箱与垃圾箱投递趋势
* 用户互动数据（打开、点击）
* 投诉与退信变化趋势

---

## 六、不合规影响

未满足上述要求时，将可能面临以下后果：

* Gmail：进入垃圾箱或被直接拦截
* Yahoo：拒收或降低投递优先级
* Microsoft（Outlook）：投递延迟或优先级下降

### 长期影响

* 域名信誉受损，恢复周期长
* IP 被列入黑名单，影响整体发送能力
