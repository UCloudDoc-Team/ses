# 使用变量发送个性化邮件

个性化是提升互动效果的关键。借助 **uSpeedo**，你无需为每位收件人单独撰写邮件，也能建立更具个人感的沟通。通过 **变量**，你可以在正文中自动插入与每位收件人相关的具体信息——例如姓名或所在地。

发送活动时，系统会将这些占位符替换为对应收件人数据中的实际值。

---

## 支持的变量

下表列出 uSpeedo 中可用的动态变量。你可以在 **邮件正文** 与 **主题行** 中使用它们。

### 联系人信息

|**变量**|**说明**|
|---|---|
|`{{first_name}}`|收件人的名字。|
|`{{middle_name}}`|收件人的中间名。|
|`{{last_name}}`|收件人的姓氏。|
|`{{email}}`|收件人的主邮箱地址。|
|`{{alternative_email}}`|收件人的备用邮箱地址。|
|`{{birthday}}`|收件人档案中的出生日期。|

### 机构与地址（发件方）

|**变量**|**说明**|
|---|---|
|`{{company}}`|你的公司名称。|
|`{{address_line_1}}`|你的主地址行。|
|`{{address_line_2}}`|你的第二地址行（如套房号、楼栋）。|
|`{{country}}`|你所在的国家或地区。|
|`{{city}}`|你所在的城市。|
|`{{state}}`|你所在的州或省。|
|`{{postal_code}}`|你的邮政编码。|

### 机构与地址（收件方）

|**变量**|**说明**|
|---|---|
|`{{recipient_company}}`|收件人所在公司名称。|
|`{{recipient_address_line_1}}`|收件人的主地址行。|
|`{{recipient_address_line_2}}`|收件人的第二地址行。|
|`{{recipient_country}}`|收件人所在国家或地区。|
|`{{recipient_city}}`|收件人所在城市。|
|`{{recipient_state}}`|收件人所在州或省。|
|`{{recipient_postal_code}}`|收件人的邮政编码。|

### 系统与日期标签

_以下标签以收件人**收到邮件时**的系统时间为准。_

|**变量**|**说明**|
|---|---|
|`{%send_date%}`|送达当日的日期。|
|`{%send_year%}`|送达年份。|
|`{%send_month%}`|送达月份。|
|`{%send_weekday%}`|送达日是星期几。|
|`{%unsubscribe_link%}`|供收件人退订的必选链接。|

## 如何插入变量

### 方法一：拖拽式编辑器

适用于在 uSpeedo 控制台中直接创建并发送活动的用户：

1. 在邮件中添加 **文本模块**。
    
2. 点击文本区域，打开编辑菜单。
    
3. 在右侧设置面板中，点击 **「添加变量」**。
    
4. 从列表中选择变量。插入后会显示为占位符（例如 `{{first_name}}`）。    

### 方法二：API 与 SMTP

若通过 API 或 SMTP 发送，只需在数据载荷中包含与变量对应的字段即可。

- **API：** 将 JSON 字段与变量名称进行映射。
    
- **SMTP：** 确保请求头或相关字段中包含所需的数据项。
    
- _具体字段结构请参阅我们的 API 文档。_

## 重要规则与最佳实践

- **默认值：** 插入变量时可设置「默认值」。当某位收件人对应字段为空时，将显示该默认文案（例如为 `{{first_name}}` 设置默认值为「客户」）。
    
- **数据源要求：** 变量需要从数据集中读取，因此仅在使用 **联系人** 或 **上传表格文件** 作为收件来源时可用。
    
    > **说明：**「粘贴邮箱」方式 **不支持** 变量，因为纯文本地址列表不包含与变量对应的元数据。
    
- **校验：** 发送前请确认收件人列表的表头中包含你计划使用的各变量对应列。若系统找不到对应字段，变量将无法正常替换。

## 常见问题

**问：可以使用自定义变量吗？**

答：可以。在上传联系人时创建的任意自定义字段，均可按 `{{custom_variable_name}}` 的格式作为变量使用。

**问：为什么收件箱里的变量显示为普通文本？**

答：常见原因是变量名拼写错误，或本次发送所使用的联系人列表中不存在该数据列。请核对列表表头与变量名是否一致。

**问：一封邮件里可以使用多少个变量？**

答：没有硬性上限，但建议按需自然使用，避免堆砌，以保持邮件可读、观感专业。
