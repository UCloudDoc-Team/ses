# Webhook 文档

Webhook 用于将邮件请求、投递、打开、点击、退订、投诉和退信等事件推送到您的业务系统。您需要先准备一个公网可访问的回调地址，并在控制台完成配置。

## 推送机制

| 项目 | 说明 |
| --- | --- |
| 请求方式 | HTTP POST |
| Content-Type | `application/json` |
| 批量推送 | 单次请求的 `Data` 数组可能包含多条事件记录 |
| 超时时间 | 默认 30 秒 |
| 失败重试 | 单个回调地址最多重试 3 次 |

业务系统应及时返回处理结果。推荐响应格式如下：

```json
{
  "code": 0,
  "message": "success"
}
```

`code` 为 `0` 表示处理成功；非 `0` 表示处理失败，并可能触发重试。

## 事件类型

| Event | 说明 |
| --- | --- |
| `request` | 邮件请求已被服务接收 |
| `deliver` | 邮件已成功投递至收件服务商 |
| `open` | 收件人打开邮件 |
| `click` | 收件人点击邮件中的链接 |
| `unsubscribe` | 收件人执行退订 |
| `report_spam` | 收件人将邮件标记为垃圾邮件或发起投诉 |
| `bounce` | 邮件因永久性原因投递失败，即硬退信 |
| `temporary_issue` | 邮件因限流、服务拥塞等临时原因投递失败，即软退信 |
| `blocked` | 邮件因域名信誉、安全策略、抑制名单或收件服务商限制被拦截 |

## 通用字段

以下字段适用于所有事件：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `SessionNo` | String | 批次或任务标识 |
| `MsgId` | String | 邮件唯一标识 |
| `Event` | String | 事件类型 |
| `ReceiptTime` | Number | 事件发生时间戳 |
| `ReceiptResult` | String | 事件处理结果 |
| `ReceiptCode` | String | 状态码或子状态码 |
| `ReceiptDesc` | String | 状态描述或失败原因 |
| `RecipientEmail` | String | 收件人邮箱地址 |
| `Domain` | String | 发信域名 |

## 事件专属字段

| 字段 | 适用事件 | 说明 |
| --- | --- | --- |
| `ExplorerName` | `open`、`click`、`unsubscribe` | 浏览器名称 |
| `ExplorerVer` | `open`、`click`、`unsubscribe` | 浏览器版本 |
| `OSName` | `open`、`click`、`unsubscribe` | 操作系统名称 |
| `OSVer` | `open`、`click`、`unsubscribe` | 操作系统版本 |
| `ClickedURL` | `click` | 被点击的链接地址 |

未适用于当前事件的专属字段可能不会出现在 JSON 数据中。业务代码不应假定所有可选字段始终存在。

## 请求示例

```json
{
  "MsgType": 2,
  "Data": [
    {
      "SessionNo": "task_123",
      "MsgId": "email_id_1",
      "Event": "deliver",
      "ReceiptTime": 1234567890000,
      "ReceiptResult": "deliver",
      "ReceiptCode": "0",
      "ReceiptDesc": "Message delivered",
      "RecipientEmail": "user@example.com",
      "Domain": "sender.example.com"
    }
  ]
}
```

## 接收与处理建议

1. 收到请求后先校验来源或签名，再解析请求体。
2. 使用 `MsgId`、`Event` 和事件时间等信息实现幂等，避免重试造成重复处理。
3. 将耗时操作交给异步任务，回调接口应尽快返回成功响应。
4. 对 `bounce`、`unsubscribe`、`report_spam` 和确认无效的地址及时停止发送，并加入抑制名单。
5. 保存必要的事件日志用于排查，但应避免记录完整邮件正文、凭证或其他敏感信息。
6. 监控回调成功率、响应时间及连续失败情况，确保回调地址长期公网可达。

!> Webhook 可能重复推送，且不同事件到达顺序不一定与实际发生顺序完全一致。请以事件标识和时间字段进行去重与状态更新。
