# DNS 服务商配置参考

不同 DNS 服务商的界面名称和填写规则略有差异，但核心配置逻辑一致：按照控制台提供的记录类型、主机记录和值逐条添加解析记录。

本文仅提供通用参考。实际配置应以 UCloud 控制台生成的记录和 DNS 服务商当前页面为准。

## 通用字段对照

| 控制台字段 | DNS 服务商中可能的名称 |
| --- | --- |
| 记录类型 | Type、类型 |
| 主机记录 | Host、Name、名称、记录名 |
| 记录值 | Value、Content、Target、指向 |
| 优先级 | Priority、优先级 |
| TTL | TTL、缓存时间 |

## Cloudflare

- 添加 CNAME 记录时，若用于邮件认证或追踪域名，通常应关闭代理状态，使用 DNS only。
- Cloudflare 可能会自动补全根域名，填写主机记录时请避免重复写入完整域名。
- TXT 记录较长时，请确认保存后未被截断。

## DNSPod

- 主机记录通常填写子域名前缀，例如 `mail`、`track` 或控制台给出的完整主机记录。
- 若是根域名记录，通常使用 `@`。
- MX 记录需要同时填写记录值和优先级。

## GoDaddy

- GoDaddy 可能将主机记录显示为 Name，将记录值显示为 Value。
- 添加子域名记录时，通常只填写子域名前缀，不需要重复填写根域名。
- 修改 NS 或 DNS 托管服务前，请确认当前域名实际使用哪一组权威 DNS。

## Namecheap

- Namecheap 的 Host 字段通常填写主机记录，Value 字段填写控制台提供的记录值。
- 若配置 CNAME，目标地址应使用控制台提供的值，不要自行替换为其他服务商地址。
- 保存后可等待一段时间再验证，避免缓存尚未刷新导致误判。

## DigitalOcean

- 若域名使用 DigitalOcean 托管 DNS，请在 Networking 的 Domains 页面添加记录。
- 添加子域名记录时，注意 Name 字段是否已经默认拼接根域名。
- MX 记录需要配置优先级，且可能影响该域名收信能力。

## 排查建议

- 确认域名当前的权威 DNS 服务商，避免在未生效的平台修改记录。
- 使用 DNS 查询工具查看公网解析结果，但最终状态以控制台验证为准。
- 若同一主机记录存在冲突，优先根据 DNS 服务商规则合并或删除无效记录。
- 修改记录后等待解析缓存刷新，再重新发起验证。
- 如需向支持团队排查，请提供域名、记录截图、解析查询结果和控制台错误提示。
