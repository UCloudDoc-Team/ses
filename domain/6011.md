# 域名认证常见问题

## 为什么需要域名认证？

域名认证用于证明您有权使用该域名发送邮件，并帮助收件服务商识别邮件来源。缺少认证或认证配置错误，可能导致邮件被拒收、进入垃圾箱或被识别为伪造邮件。

## DNS 已配置，为什么验证仍失败？

常见原因包括：

- 记录类型选择错误。
- 主机记录填写不完整或重复包含根域名。
- 记录值复制不完整，存在空格、换行或字符缺失。
- 同名记录发生冲突或被覆盖。
- 修改的不是当前生效的 DNS 服务商。
- DNS 缓存尚未刷新。

请逐条对比控制台给出的记录，并等待解析生效后重新验证。

## 应该使用主域名还是子域名？

建议使用专用子域名发送邮件，例如 `mail.example.com` 或 `notify.example.com`。如果直接使用主域名发信，发送风险可能影响官网、企业邮箱或其他业务域名信誉。

## 可以多个服务商同时配置同一个域名吗？

同一个域名可以存在多个用途的 DNS 记录，但 SPF、DKIM、DMARC 等记录需要避免冲突。若您正在从其他邮件服务商迁移，请确认旧记录是否仍需保留，并评估是否会影响认证结果。

## 修改 DNS 会影响正在发送的邮件吗？

可能会。删除或修改 SPF、DKIM、DMARC、MX、CNAME 等记录，可能导致认证失效、签名验证失败或追踪异常。生产环境修改前应评估影响，并尽量避开发送高峰。

## 认证通过后还需要保留 DNS 记录吗？

需要。域名认证不是一次性操作，收件服务商会在邮件投递过程中持续查询相关 DNS 记录。删除认证记录可能影响后续发送和投递表现。

## 验证通过是否等于邮件一定进入收件箱？

不等于。域名认证是发信基础条件之一，最终落点还会受到发信信誉、发送节奏、收件人质量、内容质量、投诉率和收件服务商策略影响。
