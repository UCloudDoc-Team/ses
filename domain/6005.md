# DNS 记录说明

邮件推送服务会在域名认证时生成所需 DNS 记录。您需要在域名 DNS 服务商处添加这些记录，让收件服务商能够识别发件身份并验证邮件来源。

## 常见记录类型

| 记录 | 常见类型 | 作用 |
| --- | --- | --- |
| SPF | TXT | 声明哪些服务器或服务商有权代表该域名发送邮件 |
| DKIM | TXT 或 CNAME | 通过数字签名证明邮件内容未被篡改 |
| DMARC | TXT | 基于 SPF 和 DKIM 定义认证失败时的处理策略 |
| MX | MX | 指定接收邮件的服务器，部分场景也用于域名认证 |
| 追踪域名 | CNAME | 用于打开、点击等行为追踪和链接跳转 |

请以控制台实际展示的记录类型、主机记录和值为准。不同账户、区域或产品策略下，记录内容可能不同。

## SPF

SPF 用于声明合法发信来源。收件服务商会检查邮件发送服务器是否在 SPF 授权范围内。

常见问题包括：

- 同一域名存在多条 SPF 记录。
- 记录值未包含实际发信服务。
- 复制时漏掉空格、引号或部分字段。
- SPF 链路过长，超过收件服务商解析限制。

## DKIM

DKIM 会为邮件添加签名，收件服务商通过 DNS 中的公钥验证签名是否匹配。DKIM 有助于证明邮件在传输过程中未被篡改。

配置时请注意选择器名称和主机记录。不同平台使用的 DKIM 选择器可能不同，不应照搬其他服务商的记录。

## DMARC

DMARC 基于 SPF 和 DKIM 工作，用于定义认证失败时的处理策略，并可提供认证报告。建议至少配置基础策略，并根据自身治理能力逐步调整。

示例策略仅用于说明格式：

```txt
v=DMARC1; p=none; rua=mailto:dmarc@example.com
```

实际配置应以控制台提示和企业安全策略为准。

## MX

MX 记录用于指定收信服务器。如果该域名还承担企业邮箱收信，请在调整 MX 记录前确认不会影响现有邮箱业务。

若控制台要求配置 MX 记录用于认证，请严格按页面提示填写优先级和值。

## 配置检查

验证失败时，建议按以下顺序排查：

1. 记录类型是否正确。
2. 主机记录是否多写或少写了域名后缀。
3. 记录值是否完整复制。
4. 同名记录是否被覆盖或冲突。
5. DNS 修改是否已经生效。
6. 是否在正确的 DNS 服务商处修改了当前生效的解析。

如需查看不同服务商的常见差异，请参考[DNS 服务商配置参考](/ses/domain/6009)。
