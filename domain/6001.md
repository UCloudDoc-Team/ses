# 发信域名概述

发信域名是邮件身份和发信信誉的基础。邮件推送服务会通过域名验证确认您拥有对应域名的管理权限，并通过 SPF、DKIM、DMARC 等记录帮助收件服务商识别邮件来源。

建议在正式发信前使用自有域名或专用子域名，不建议长期使用临时或共享身份发送生产邮件。

## 主域名与子域名

主域名通常承载官网、业务系统或企业邮箱，例如 `example.com`。如果直接使用主域名发送大量邮件，退信、投诉或内容风险可能影响主域名信誉。

更推荐使用专用子域名承载邮件发送，例如：

| 用途 | 示例 |
| --- | --- |
| 事务通知 | `mail.example.com`、`notify.example.com` |
| 营销活动 | `marketing.example.com`、`news.example.com` |
| 链接追踪 | `track.example.com` |

将不同用途拆分到不同子域名，有助于隔离信誉风险，也便于后续按业务类型分析投递表现。

## 发信域名的作用

- 证明您有权使用该域名发送邮件。
- 降低邮件被识别为伪造或钓鱼邮件的风险。
- 为后续发信信誉积累提供稳定身份。
- 支持按域名查看发送、退信、投诉和互动数据。

## 使用建议

- 新业务优先使用专用子域名，不要直接复用网站主域名。
- 事务邮件和营销邮件尽量使用不同域名或子域名。
- 不要频繁更换发信域名，域名信誉需要持续积累。
- 删除 DNS 认证记录前，确认该域名不再承担生产发送。
- 域名认证通过后，先小流量测试，再逐步扩大规模。
