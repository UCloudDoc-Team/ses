# SMTP 发信指南

SMTP 适用于需要通过标准邮件协议接入 UCloud 邮件推送服务的业务系统。开始发信前，请先完成发信域名验证，并创建可用的发信地址。

## 开启 SMTP 发信

1. 登录 UCloud 控制台，进入邮件推送服务。
2. 在左侧导航栏选择**邮件配置 > 发信地址**。
3. 找到需要使用 SMTP 发信的地址，在操作栏中选择**设置 SMTP 密码**。
4. 按页面提示设置密码并保存。

!> SMTP 密码是发信凭证，不是 UCloud 账户登录密码。请勿将密码写入前端代码、公开仓库或日志。

## 配置 SMTP 客户端

在邮件客户端或业务程序中填写以下信息：

| 配置项 | 说明 |
| --- | --- |
| SMTP 服务器 | 以控制台或产品页面展示的服务器地址为准 |
| 端口及加密方式 | 按控制台说明选择对应端口，并启用要求的 TLS/SSL 加密方式 |
| 用户名 | 使用控制台提供的 SMTP 用户名或发信地址 |
| 密码 | 使用为该发信地址设置的 SMTP 密码 |
| 发件人 | 应与已验证、可用的发信地址保持一致 |

不同语言和邮件组件的参数名称可能不同，但均应使用上述凭证完成 SMTP 身份验证。

## 发送测试邮件

首次接入时，建议只向您可控制的邮箱发送测试邮件，并检查：

- SMTP 客户端是否成功建立加密连接并通过身份验证。
- 发件人地址是否与控制台配置一致。
- 邮件主题、正文、字符编码和附件是否正常。
- 不同收件服务商是否可以正常接收邮件。
- 投递记录中是否产生对应的发送与投递状态。

## 发送建议

- 新域名应从小流量开始，根据退信率、投诉率和送达情况逐步增加发送量。
- 不要在短时间内对同一收件人重复发送，以免触发频率限制或反垃圾策略。
- 复用 SMTP 连接时，应正确处理连接超时、服务端断开和临时错误。
- 对临时失败实施有限次数的退避重试；对永久失败或无效地址停止重试。
- 定期轮换 SMTP 密码。发现凭证泄露或异常发送时，应立即更换密码并暂停相关任务。

?> SMTP 请求被服务接受不代表邮件最终送达。请结合投递记录或 Webhook 事件确认最终状态。
