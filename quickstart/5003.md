# 邮件发送

本文介绍完成首次发送、测试和结果确认的基本流程。邮件配置尚未完成时，请先阅读[邮件配置](/ses/quickstart/5001)。

## 1. 发送前检查

- 发信域名已完成验证，DNS 记录仍然有效。
- 发信地址状态正常，发件人名称和回复地址符合业务用途。
- 模板或邮件内容可以使用，变量字段已经准备好。
- 收件地址来自合法、明确授权的业务场景。
- 收件地址不在退订、投诉、硬退信或其他抑制名单中。
- 测试邮件中的变量、链接、图片和字符编码显示正确。

如果是新域名、长期未发信域名或大批量任务，请先阅读[域名预热](/ses/deliverability/6105)和[发送速率](/ses/guide/send/7107)。

## 2. 选择发送方式

根据发送规模和业务类型选择：

| 方式 | 适用场景 | 参考文档 |
| --- | --- | --- |
| 普通发送 | 单封测试、事务通知、少量收件人 | [普通发送](/ses/guide/send/7101) |
| 批量发送 | 面向已授权的收件人列表发送通知或活动 | [批量发送](/ses/guide/send/7105) |
| SMTP | 业务系统通过标准邮件协议接入 | [SMTP 发信指南](/ses/smtp/8001) |
| API | 业务系统按接口提交发送请求 | 以当前 API 文档和控制台说明为准 |

## 3. 通过控制台发送

1. 进入“邮件发送”，选择普通发送或批量发送。
2. 选择已验证域名下的发信地址和可用模板。
3. 填写收件人、主题、正文或模板变量。
4. 预览邮件，检查发件人、主题、正文、链接、图片和变量替换结果。
5. 首次使用或内容变更后，先发送到内部测试邮箱。
6. 确认测试结果无误后，再创建正式发送任务。

批量任务在创建前，还应核对预计收件人数、变量字段、发送时间、退订路径和发送速率。

## 4. 发送后查看

发送任务创建后，先查看发送记录，确认请求是否被服务接受，再查看投递回应，确认收件服务器的处理结果。

- **请求已接受**：表示服务已接收请求，不代表邮件最终送达。
- **已送达**：表示收件服务器已接收，不保证邮件进入收件箱。
- **软退信**：通常是临时问题，可按策略有限重试。
- **硬退信**：通常是地址或域名永久不可用，应停止发送。
- **已拦截**：需要结合失败描述检查信誉、认证、内容或收件服务商限制。

详细状态说明请参考[投递回应](/ses/guide/7203)。

## 5. 分析发送结果

在[数据统计](/ses/guide/7201)中按时间、域名、发信地址或任务筛选，重点查看：

- 请求量、接受量和已送达量。
- 硬退信、软退信和拦截原因。
- 打开、点击、退订和投诉趋势。
- 不同收件服务商的异常变化。

如果需要让业务系统自动同步状态，请配置[回调地址](/ses/guide/config/7007)，并按[Webhook 文档](/ses/webhook/8201)处理重复事件和事件顺序问题。

## 6. 异常处理

### 测试邮件没有收到

请先检查垃圾箱、推广分类、发件人地址和主题搜索结果，再查看发送记录和投递回应。若显示软退信或限流，可暂时降低发送速率。

### 批量任务失败较多

暂停继续放量，检查域名认证、收件人列表、模板链接、发送节奏和失败原因。不要对硬退信、退订和投诉地址重复发送。

### 邮件进入垃圾箱

邮件进入垃圾箱不一定表示投递失败。请检查域名认证、发信信誉、发送节奏、名单授权和内容质量，参考[降低垃圾邮件风险](/ses/deliverability/6107)。

程序化发送时，请妥善保管访问凭证，不要将密钥写入前端代码或公开仓库。
